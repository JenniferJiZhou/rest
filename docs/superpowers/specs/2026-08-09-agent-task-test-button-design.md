# Agent 任务测试按钮设计

## 目标

在 iPhone 与 Mac 的 Hush 设置页中增加一致的“测试 Agent”入口。用户点击后，Hush 使用当前设置中的 Agent HTTPS 地址和当时可取得的最小真实上下文发送主动休息请求，并在设置页内展示 Agent 返回的任务标题、建议时长、步骤和简短说明。

这不是一次性的调试代码。请求与状态管理应成为未来“用户通过手势主动进入休息”功能可复用的底层能力；未来手势只负责触发同一流程，不重新实现网络请求。

## 范围

本次包含：

- iOS 设置页 Agent 区域中的测试按钮与结果展示；
- Mac 设置页 Agent 区域中的测试按钮与结果展示；
- 共享的 Agent 测试任务请求与状态模型；
- 请求前可见的“本次将发送的数据”摘要；
- 现有 `/v1/rest/recommend` Contract 1.1 的可选真实上下文字段；
- 真实数据来源与 Mock 数据来源的明确标记；
- 成功、失败、请求中和重复点击行为的自动化测试。

本次不包含：

- 上滑、下滑、长按或其他主动休息手势；
- 自动开始休息任务或离开设置页；
- 将测试任务写入正式任务、历史记录或提醒系统；
- 新增服务器端测试专用接口；
- 修改现有视觉风格或页面结构。
- 收集、训练或调整任何个人学习数据与触发阈值。

## 交互设计

两端都在现有 Agent 设置区域内增加“测试 Agent”按钮。

- Agent 地址无效时按钮禁用，并沿用现有地址错误提示。
- 请求进行中时按钮禁用，标签替换为进度指示，防止重复请求。
- 设置页在按钮附近展示“本次将发送的数据”，用户点击按钮即表示发送该摘要中的内容。
- 每次点击使用新的请求 ID，读取当时可取得的最小真实上下文；不读取消息、文件、输入内容、完整网址或页面标题。
- 成功后在按钮下方展示一个结果区域：Agent 说明、任务标题、建议时长和有序步骤。
- 结果区域必须显示“真实 Agent”或“测试数据”。该标记来自响应的 `X-Hush-Data-Origin`，不能根据客户端猜测。
- 再次点击会替换上一次结果。
- 失败时保留设置页并显示可理解的内联错误；用户可以再次点击重试。
- 成功后不自动跳转，也不提供“开始任务”按钮。本次只验证并查看 Agent 返回内容。

## 架构

### 共享请求层

扩展现有 Contract 1.1 主动休息请求能力，使调用方能同时获得：

- `HushDynamicRestSuggestion`；
- 服务端声明的数据来源 `real` 或 `mock`。

生产请求继续调用现有 `/v1/rest/recommend`，不增加服务器路由。客户端必须校验现有契约头、请求 ID、响应结构和 `X-Hush-Data-Origin`；缺失或未知的数据来源视为无效响应。

现有 Contract 1.1 主动休息请求只包含疲劳、偏好、可用时间、来源和位置，无法携带使用摘要。本次在同一路由的 Contract 1.1 请求中增加可选的 `decision_context`：旧客户端不发送该字段时行为保持不变；新版服务器验证并将它传给主动休息 Prompt，只用于本次实时推理。

`decision_context` 包含：测量时间、平台、用户主动填写的上下文名称、当天分钟数、连续分钟数、是否为估算、最近十分钟切换次数、距离上次休息分钟数、本地小时，以及固定为 `false` 的原始 App 名称、完整网址、页面标题和学习资格标记。不可取得的可选数值使用 `null`，不能伪造为零。

服务器继续对请求正文执行日志脱敏。`learning_eligible` 必须为 `false`，`source` 必须是平台对应的设置测试来源；服务端在契约边界拒绝不符合该组合的测试请求。

### 共享状态层

新增一个小型、可注入请求依赖的主线程状态模型，负责：

- 校验并接收当前设置中的 Base URL；
- 管理 `idle`、`loading`、`success`、`failure` 状态；
- 接收平台提供的当前测试上下文；
- 阻止并发重复请求；
- 将网络错误转换成用户可读消息。

iOS 与 Mac 设置页各自持有该状态模型，并把当前文本框中的 Base URL 传入测试操作。未来主动休息手势可直接复用同一请求协议和结果类型，但不复用设置页专属视图状态。

### 真实测试上下文

测试请求只包含生成任务所需、且在发送前可见的最小真实信息：

- 新生成的测试 session ID；
- 用户主动填写的活动或 App 名称；
- 连续使用分钟数及其是否为估算值；
- 当天累计分钟数；
- 最近十分钟的 App 切换次数；
- 距离上次休息的分钟数；
- 当前本地小时；
- fatigue type：没有用户输入时为 `unknown`；
- preference：`surprise`；
- available minutes：`3`；
- source：按平台区分的 `settings_agent_test` 来源；
- location tags：空数组。

Mac 使用当前监测模型已经掌握的实时摘要。iOS 使用最近一次可合法取得的 Device Activity 摘要；如果系统限制导致某项即时数据不可用，该字段明确显示并发送为“未知”或估算值，客户端不得编造数据。

不发送 Bundle ID、未经用户填写的系统 App 名称、完整网址、页面标题、消息、文件或输入内容。

测试请求的来源必须明确标记为测试用途，且不得写入未来的个人学习事件、触发阈值或任务偏好记录。本期按钮回答三个问题：客户端能否连接当前 Agent，Agent 能否根据真实上下文做决策，以及 Agent 能否按契约返回一项可展示的休息任务。

## 后续个性化边界

未来的主动休息手势属于独立功能，不在本次实现中。该功能应使用真实的当时上下文，并将事件标记为 `user_initiated`；只有此类真实事件及其后续的开始、完成、推迟、关闭和反馈才可参与当前用户的个人学习。

个人学习只服务于当前用户，不使用一个用户的数据调整其他用户。测试按钮产生的事件始终排除在学习数据之外，即使请求中包含真实上下文。未来可以复用本次建立的 Agent 请求协议和任务结果类型，但必须单独设计个人事件存储、隐私说明、阈值调整边界和恢复默认能力。

Hush 不将本次上下文写入个人学习记录。服务端只允许为完成当前请求和现有幂等处理进行必要的短期处理；请求正文继续从应用日志中移除。连接第三方模型时，发送内容仍会由模型服务商按照其服务条款处理。

## 错误处理

- 无效或非 HTTPS 地址：客户端不发请求。
- 网络、超时或非 2xx：显示“无法连接 Agent，请检查地址或稍后重试”。
- 契约头、请求 ID、数据来源或正文无效：显示“Agent 返回了无法识别的任务”。
- 返回 Mock：正常展示任务，但以“测试数据”清楚标记，不冒充真实模型结果。
- 返回 Real：正常展示任务，并标记“真实 Agent”。

错误消息不显示密钥、完整请求正文、内部响应或堆栈。

## 测试策略

遵循测试驱动开发：先编写失败测试，再实现最小代码。

自动化测试覆盖：

- 成功解析真实来源任务；
- 成功解析 Mock 来源任务；
- 缺失或非法数据来源被拒绝；
- 旧版不带 `decision_context` 的 Contract 1.1 请求保持兼容；
- 设置测试请求只能携带 `learning_eligible: false`；
- Agent Prompt 收到经过校验的真实上下文；
- 无效 HTTPS 地址不发请求；
- 发送摘要不包含 Bundle ID、完整网址、页面标题、消息或输入内容；
- 平台缺失数据被标记为未知或估算，不能伪造成精确数据；
- 请求中拒绝第二次触发；
- 成功结果包含标题、时长、步骤和说明；
- 网络及契约错误进入失败状态；
- iOS 与 Mac 构建目标都包含共享实现。

完成后运行 iOS 测试、iOS 构建、Mac 构建和服务器现有完整检查，确认没有 UI 资源变化。

## 成功标准

- iPhone 和 Mac 设置中都能看到“测试 Agent”。
- 对当前线上地址点击一次后，设置内出现一个任务或明确错误。
- 结果明确区分真实 Agent 与测试数据。
- 只发送设置页预览的最小真实上下文，不自动进入任务，不改变现有手势。
- 不产生可用于个人学习的记录。
- 所有新增测试及现有验证门禁通过。
